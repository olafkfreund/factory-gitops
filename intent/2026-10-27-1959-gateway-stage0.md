# Intent: model gateway stage 0 — deployed, verified, unused

## Problem

Factory#1959 moves every model call behind one in-house gateway. Since
AIFactory 3.10.12 the gateway image is built and cosign-signed as
`ghcr.io/olafkfreund/aifactory:*-gateway`
(AIFactory `plan/2026-10-27-1959-gateway-image.md`), but nothing runs it.
Stage 0 of the epic is to run it in the cluster with nothing routed through it,
and to prove admission actually checks its signature.

The AIFactory plan said the existing Kyverno glob covers the tag "so there is
no gitops change". That is true for the image name and false for the
namespace: every first-party rule in `verify-factory-image-signatures`
matches Pods in `namespaces: [factory]` only (checked on the live cluster
2026-10-27). A gateway in its own `gateway` namespace would be admitted with
no signature check and no PolicyReport result — the green-from-absence shape
of Factory#564, and the epic's risk #2.

## Proposed outcome

- An Argo app `model-gateway` runs the gateway in a new `gateway` namespace,
  pinned by digest, hardened, with health probes, a ClusterIP Service, a PDB
  and default-deny NetworkPolicies.
- It is unconfigured: no upstream, no client token, no provider key. `/healthz`
  returns 200 and `POST /v1/chat/completions` returns 503.
- Kyverno verifies its signature at admission: a PolicyReport PASS result
  exists for it, and an unsigned `aifactory:*` reference in `gateway` is
  denied (server-side dry-run).
- No service calls it.

## Affected users and systems

- k3d cluster on p620: new namespace `gateway`.
- `apps/kyverno-policies`: the aifactory signature rule and the coverage
  policy also match `gateway`.
- New `apps/model-gateway`. Nothing in `factory` changes.

## Constraints

- No secrets or provider keys; factory-gitops is public.
- Not part of the `aifactory` kustomization: AIFactory's `deploy.yml` runs
  `kustomize edit set image aifactory=` there and would repoint the gateway.
- The policy scope change must be live before the gateway Pod is admitted, or
  the Pod is admitted unverified.
- Never `--admin` or force-push. Post on the agent bus before the deploying
  merge. Revert via PR if anything crashloops.

## Remaining slices (epic order, after this one)

1. Stage 1 — CFactory copilot chat through the gateway; configure upstream +
   client token (out-of-band Secret), add the single upstream to the egress
   allowlist, then remove `OLLAMA_API_KEY` from CFactory.
2. Stage 2 — TFactory verify path (manifest and `verify_dispatch.py`).
3. Stage 3 — routes in the contract (`route`/`phase_routes`), ConfigMap

4. Stage 4 — AIFactory + PFactory (Plane A), incl. `_PASSTHROUGH_BUILD_ENV`.
5. Stage 5 — Plane B (Claude OAuth), after the bench test.
6. Stage 6 — rotate every provider credential.
